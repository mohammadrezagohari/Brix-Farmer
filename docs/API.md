# API conventions

Dashboard milestone (supersedes earlier foundation limitations): API controllers now provide `/workspace/dashboard`, `/workspace/inventory`, `/inventory-lots/{lot}/movements`, `/incoming-reservations`, GET/PUT `/organization-profile`, GET/POST `/listings`, GET/PUT `/listings/{listing}`, POST `/listings/{listing}/transition` (submit/pause), `/marketplace` and `/marketplace/{listing}`. All require active user and verified organization membership context; marketplace shows only published listings from verified unsuspended suppliers. Listing detail is not a private stock/warehouse endpoint. Draft details permit incomplete quantities; submission requires valid quantity/minimum, grade and country. Submitted quantity/unit/origin cannot be edited. A new submission creates kg stock using BCMath for kg/tonne conversion, not a purchase acquisition.

Admin Gate protects users/suspension, organizations/review, listings/review, categories and audit-logs. Decisions require reason, and KYB requires evidence text/references plus a complete legal profile. No uploaded-document review or regulatory clearance is implied. Profile changes reset KYB eligibility. Suspension is checked on each authenticated request; logout remains allowed.

Private `/trade-partners` and `/opportunities` support create/list, plus PATCH `/opportunities/{opportunity}/stage`. Partner references are organization-scoped. CRM won/lost does not create an order or transfer stock. All new lists paginate and applicable list searches accept q; listings/organizations accept status, marketplace accepts country/category. `node scripts/update-openapi.mjs` regenerates implemented route/method inventory and request schemas in docs/openapi.json from Laravel route:list.

Extension: authenticated `GET admin/dashboard` (users, organizations, pending_organizations, inventory_lots counts) and `GET admin/organizations` (20-row pagination) require the platform-admin Gate. `GET trader/dashboard` requires X-Organization-ID and owner/manager/buyer/trader membership, returning inventory_lots and active_reservations counts scoped to that organization. No global admin inventory bypass exists. `POST organizations` accepts optional `type: supplier|trader`; trader creates trader membership, otherwise owner. Trader may create lots, reserve and release alongside existing authorized roles. User responses include boolean is_platform_admin. Registration ignores that field and cannot grant it. Admin approval/moderation mutations remain outside this change.

Base /api/v1. JSON requests, Accept: application/json. Stateful Sanctum authentication via Laravel session cookie. Fetch GET /csrf first; send its token as X-CSRF-TOKEN on all writes. Refresh it after authentication changes. Browser traffic uses the same frontend origin; Next rewrites to API_ORIGIN, default http://127.0.0.1:8000.

GET health; GET csrf; POST register (name,email,password,password_confirmation); POST login (email,password). Authenticated: GET me, POST logout, GET/POST organizations (create: name). Organization inventory routes require X-Organization-ID, validated against active membership. GET/POST inventory-lots (product, origin_country uppercase ISO alpha-2 format, on_hand_kg, minimum_order_kg). Quantities must be positive decimal JSON strings, at most three decimal places. GET reservations; POST inventory-lots/{id}/reservations (quantity_kg and Idempotency-Key header); POST reservations/{id}/release. Reservation HTTP access requires a verified unsuspended supplier. There is no public lot discovery until listing moderation and visibility exist.

Creates return 201 with data; resource reads use data; collection pagination uses Laravel paginator (20 records). Release/logout: 204. Validation: 422 with message/errors, authentication 401, authorization 403, unavailable resource 404, insufficient stock or changed idempotency input 409, CSRF 419, throttling 429. No arbitrary status writes. A reservation is a temporary hold, never proof of purchase, payment or ownership.

Routes currently use closures; thin controllers, Resources and full policy extraction remain a refactor requirement. The original OpenAPI reference was absent; openapi.json documents only implemented routes.
